## 1. What is breaking us (ranked)

### 1.1 Layout strings are JSON now; our `<...>` float suffix is gone

Upstream replaced the layout string with a JSON subset ("V":2) that carries
floating panes, z-order and the last-pane order natively (`json.c`,
`layout-custom.c` rewritten, Dane Jensen). The old v1 format is still
parsed, and control-mode clients keep receiving v1 unless they set the
`new-layouts` client flag.

Our fork extended v1 with a `<...>` section listing floating cells after
the tiled tree, and three consumers parse it:

- `remote-link.c` / `remote-parse.c`: `remote_parse_layout_strip` splits
  the suffix off and `remote_link_restore_floats` re-creates floats on the
  shadow window. Over a link to a merged (or upstream) server the suffix
  never arrives, so remote floating panes stop being mirrored. Fix: set
  `new-layouts` on the link's control client and feed the v2 string to
  `layout_parse`, which now rebuilds floats and z-order itself. Most of
  `remote_link_apply_layout`'s float juggling can go.
- `server-handoff.c`: wrote `layout_dump_part(w, root, 0)` (tiled only)
  and restored floats from their own records. In the trial merge this is
  `layout_dump(w, root, LAYOUT_CUSTOM_OLD_FORMAT)`, which upstream's v1
  dumper also writes tiled-only, so the handoff keeps working as is. It
  could switch to v2 and drop the float records.
- `plugin-host/examples/resurrect/src/lib.rs` `split_layout`: parses
  `#{window_layout}` as "checksum, tiled tree, `<floats>`". A plain (non
  control) client now gets v2 JSON from that format, so the parser falls
  back to "no floats" at best. Needs a JSON path.

Related: upstream also fixed "Correctly write Z indexes to v2 layouts if
zoomed" (`4624bc21`), the same class of bug as our zoomed-layout crash
chain from Sep 24-25.

### 1.2 Popups and the overlay machinery are gone

`34cd5da4` removed `popup.c` and the client overlay callbacks.
`display-popup` survives as an undocumented shim that opens a modal
floating pane with `PANE_CAPTUREALLKEYS`, honours `-E`/`-EE`, `-k`, `-w`,
`-h`, `-x`, `-y`, `-T`, `-s`, `-S`, `-b`/`-B`, `-c`, `-d`, `-e`.

- Our C additions do not use the overlay API (checked: remote-*, plugin-*,
  server-handoff, window-plugin-mode).
- The scp plugin runs its copy in `display-popup -c <client> -EE -w 80%
  -h 30% -T ...`; the shim accepts all of that, so it should keep working
  but now behaves as a modal floating pane. Worth a manual check.
- `input_init()` lost its `struct client *` argument (it existed for popup
  replies). One call in `window-plugin-mode.c` fixed in the trial merge.

### 1.3 Our push/pop modal zoom was superseded

Upstream added `new-pane -A` / `SPAWN_FLOATOVERZOOM` / `PANE_FLOATOVERZOOM`
("a way for floating panes to stay above zoom, used by default for modal
panes", `95a71707`) and `window_push_zoom(w, 0, 1)`. The merge silently
deleted our `window_push_modal_zoom`/`window_pop_modal_zoom` and the
callers in `spawn.c` (editor pane), `layout.c` and `cmd-split-window.c`
took upstream's versions. The trial merge drops the last caller in
`window_remove_pane`. Behaviour of our editor/modal panes after a zoom
needs re-testing (regress `plugin-mode-zoomed.sh`, `remote-zoom-floats.sh`).

### 1.4 Helpers we made public that upstream deleted or made static

- `layout_fix_zindexes` was removed upstream (layout_parse owns the z-order
  now). `remote-link.c`'s fallback path still calls it; re-added as our own
  function in the trial merge.
- `layout_checksum` is static again; `remote-parse.c` already has its own
  copy, nothing else used it.
- `layout_dump_part` is gone (see 1.1).

### 1.5 Flag bit collisions (silent without the conflict)

`PANE_NORESIZETRIM` and `PANE_REMOTE` collided with upstream's new
`PANE_CLOSEONCLICK`/`PANE_CAPTUREALLKEYS`; `SPAWN_ADOPT` collided with
`SPAWN_FLOATOVERZOOM`. Renumbered in the trial merge (0x800000, 0x1000000,
0x2000). A scripted check of the merged `tmux.h` found no other duplicate
bit within a flag family, no duplicate option names, and the format table
is still sorted (bsearch) with no duplicate entries.

### 1.6 Control mode changes that touch the remote link

- Notifications are queued and never emitted inside `%begin`/`%end`
  (`6db5175e`). Our parser handled both, so this only removes a case.
- Buffered replies are capped at 64 MB; past that the client gets
  `CLIENT_CONTROL_DISCARD` and output is dropped (`a3129249`). A link
  reader that stalls now loses output instead of growing the server.
- Control clients that have been destroyed are no longer written to; NULL
  checks for clients that have not identified yet; a stuck client no
  longer blocks server exit (10 s give-up).
- `refresh-client -f new-layouts` is the opt-in for v2 layouts (see 1.1).
- `display-popup` is a no-op for control clients.

### 1.7 Copy mode: `r` binding

Upstream's `r` is `refresh-now` (one-shot) with `refresh-on/off/toggle`
as commands; our `|` → `live-toggle` binding and `live-*` commands sit
beside them in the trial merge. The two features overlap (live copy mode
scrolls alt-screen apps via synthetic wheel events; upstream refresh only
redraws). Decide whether to keep both.
